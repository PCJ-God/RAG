# 系统工作流程（详细版）

本文档记录 RAG 知识答疑助手的完整工作流程，分两部分：

- **第一部分：离线流程** —— 索引构建（一次性 / 周期性执行）
- **第二部分：在线流程** —— 用户单次提问时系统内部的完整处理过程

所有步骤均标注了对应的源码位置（`文件:函数/类`），便于对照阅读。

---

## 0. 总览

系统由两条流程组成：

```
离线流程（构建索引，一次性）
    文档加载 → 结构感知分块 → 向量化 → 写入向量库（本地 JSON / DashVector）
         ↓ 产物
    向量索引（knowledge_base/<domain>/ 或 DashVector collection）

在线流程（每次提问，实时）
    输入护栏 → 记忆加载 → 意图识别(改写/拆解/追问) → 标签抽取
            → 混合检索 → 重排 → 生成 → 输出护栏 → 记忆写回
```

- 离线流程的入口：`scripts/build_index.py` → `RAGPipeline.build()`
- 在线流程的入口：`scripts/ask.py` → `RAGPipeline.query()`；评测走 `scripts/eval.py` 直接调 `pipeline.query()`

核心配置来源：`.env`（经 `src/config.py` 的 `Config.from_env()` 读取，`load_dotenv(override=True)` 保证 `.env` 为权威）。

# 第一部分：离线流程（索引构建）

## 1. 入口与调用链

```
scripts/build_index.py:main()
  └─ RAGPipeline(domain=args.domain)        # 创建 pipeline，初始化配置与依赖
       └─ pipeline.build(domain, rebuild)   # 构建索引
            ├─ MarkdownLoader(...).load()          # 加载文档
            ├─ QualitySplitter(...).get_nodes()    # 结构感知分块
            └─ Indexer(...).build(nodes)           # 向量化 + 写入索引
```

关键参数：
- `domain`：知识域目录名，默认 `rag`，对应 `data/knowledge/<domain>/`
- `--rebuild`：强制重建（本地覆盖文件；DashVector 先删旧 collection 再建）
- 若索引已存在且未加 `--rebuild`，脚本直接退出（`indexer.exists()` 判断）

## 2. 文档加载（`src/document/loader.py`）

类 `MarkdownLoader`，内部用 LlamaIndex 的 `SimpleDirectoryReader`：

- 递归读取 `data/knowledge/<domain>/` 目录下所有 `.md` 文件（`required_exts=[".md"]`, `recursive=True`）
- 每个文件读入为一个 LlamaIndex `Document` 对象
- 目录不存在时抛 `FileNotFoundError`

## 3. 结构感知分块（`src/document/splitter.py`）

类 `QualitySplitter`，参数 `chunk_size=512`、`chunk_overlap=50`。分四步：

### 3.1 按标题层级切小节

用 `MarkdownNodeParser` 先按 Markdown 标题层级（`#`/`##`/`###`…）把每个文档切成若干"小节"，保证每个块语义完整。标题路径自动写入块元数据的 `header_path` 字段（例如 `2.1 RAG工作原理 > 1. 建立索引`）。

### 3.2 超长小节语义切分

对超过 `chunk_size`（512 字）的小节，用 `SemanticSplitterNodeParser`（embedding 断裂点法）二次切分：先按句计算相邻句的向量余弦相似度，在相似度骤降处（超过 `semantic_breakpoint_threshold=95` 百分位）切分，使语义相近的句子聚成一个块，同时继承 `header_path`、`tag`、`file_name` 元数据。

语义切分可能产生超长块，`_enforce_cap` 会对仍超过 `chunk_size` 的块再用 `SentenceSplitter` 按句子硬切兜底。

### 3.3 文本清洗

`_clean()` 处理 Notebook 导出产生的噪声：去掉 HTML 标签（`<[^>]+>`）、`html.unescape` 反转义、`\u00a0` 替换为空格、压缩连续空格、把 3 个以上连续换行压缩为 2 个。

### 3.4 打标签 + 组装元数据

每个块最终只保留三个扁平元数据字段（兼容 DashVector 的 flat_metadata 校验，值必须为 str/int/float/None）：

| 字段 | 值来源 | 用途 |
| --- | --- | --- |
| `tag` | `get_tag(file_name)`，查 `src/config.py` 的 `TAG_MAP`（按文件名映射，未命中为"其他"） | 标签检索的过滤字段 |
| `file_name` | 文档文件名 | 引用溯源 |
| `header_path` | 章节标题路径 | 引用溯源（精确到小节） |

## 4. 向量化（`src/embedder.py`）

类 `CompatibleEmbedding`，自定义实现 LlamaIndex `BaseEmbedding`：

- 模型：`text-embedding-v3`（DashScope 专有模型名，OpenAIEmbedding 枚举不认，故自定义）
- 走 OpenAI 兼容协议：`BASE_URL = https://dashscope.aliyuncs.com/compatible-mode/v1`
- 输出维度：**1024 维**
- 批量：`EMBED_BATCH_SIZE = 10`（兼容模式单次最多 10 条）
- 同时提供查询向量与文本向量接口（`_get_query_embedding` / `_get_text_embedding`）

## 5. 索引写入（`src/indexing/indexer.py`）

类 `Indexer`，`build(nodes, rebuild)` 按 `.env` 的 `VECTOR_STORE` 分两种后端：

### 5.1 本地 JSON 模式（`VECTOR_STORE=local`，默认）

```
VectorStoreIndex(nodes, embed_model)
  └─ index.storage_context.persist(persist_dir)
       └─ 写入 knowledge_base/<domain>/ 目录（docstore.json 等）
```

- 向量化在建索引时同步完成（对每个块调 embedding）
- `exists()` 判断 `knowledge_base/<domain>/docstore.json` 是否存在
- 零依赖，开发友好

### 5.2 DashVector 模式（`VECTOR_STORE=dashvector`）

```
get_collection(config, "<domain>_knowledge", dim=1024, fields_schema={"tag": str}, create=True, drop_first=rebuild)
  └─ PatchedDashVectorStore(collection)     # 修复 llama-index-vector-stores-dashvector 0.2.0 的 bug
       └─ VectorStoreIndex(nodes, storage_context=..., embed_model)
            └─ 写入阿里云 DashVector collection
```

关键点：
- collection 名为 `<domain>_knowledge`（可经 `DASHSVECTOR_COLLECTION` 覆盖）
- 维度 1024（`text-embedding-v3`，建库后不可改）
- 额外定义了 `tag` 字段（`fields_schema={"tag": str}`），供标签检索的字段过滤使用
- DashVector 创建是异步的，`get_collection` 内部会轮询 `stats()` 直到可用
- `PatchedDashVectorStore` 修复上游 0.2.0 两个 bug：未实现抽象属性 `client`；漏初始化 `_support_sparse_vector/_encoder`
- `exists()` 用 `client.list()` 判断（`client.get()` 对不存在的 collection 也返回句柄）

## 6. 离线流程产物

| 模式 | 产物位置 |
| --- | --- |
| 本地 | `knowledge_base/rag/`（`docstore.json` 等持久化文件） |
| DashVector | collection `rag_knowledge`（含 `tag` 字段） |

# 第二部分：在线流程（单次提问）

## 1. 前置：pipeline 初始化（`src/pipeline.py:RAGPipeline.__init__`）

每次启动问答（`scripts/ask.py`）时执行一次，非每次提问：

1. `check_api_key()` —— 校验 `.env` 的 `DASHSCOPE_API_KEY` 已配置
2. `create_embed_model()` —— 创建 embedding 模型并注册到 `Settings.embed_model`（全局默认）
3. 创建 `LLMClient`（OpenAI 兼容协议），并挂到 `Settings.llm`
4. 实例化各组件：`AnswerGenerator` / `TagExtractor` / `QueryRewriter` / `QueryDecomposer` / `IntentAnalyzer` / `ContentGuard`
5. `load()` 加载索引（`Indexer.load()`），组装 `FusionRetriever` 与 `Reranker`
   - 若索引不存在抛 `FileNotFoundError`，提示先跑 `build_index.py`
   - 本地模式：`load_index_from_storage` 从磁盘加载
   - DashVector 模式：`VectorStoreIndex.from_vector_store(PatchedDashVectorStore)`，并把原始 `collection` 赋给 `indexer.collection`（供标签路使用）

> `session_id=None` 时（单次命令行提问、评测）不启用记忆；交互模式会生成随机 `session_id`，`--session-id` 可恢复会话。

## 2. 完整调用链（`src/pipeline.py:query()`）

```
query(question)
  ├─ ① 输入护栏        ContentGuard.check_input(question)
  ├─ ② 记忆加载        （可选）画像 + 历史
  ├─ ③ 意图识别        IntentAnalyzer.classify(question) → 单意图/多意图/需追问
  ├─ ④ 改写/拆解/追问  （三选一）
  ├─ ⑤ 检索生成        单意图 _single_pass / 多意图 _multi_pass
  ├─ ⑥ 输出护栏        ContentGuard.check_output(answer)
  ├─ ⑦ 记忆写回        （可选）会话记忆 + 全局事实
  └─ 返回 Answer(answer, sources)
```

## 3. ① 输入护栏（`src/safety/guard.py:ContentGuard`）

- 调用阿里云内容安全（绿网）`llm_query_moderation` 服务检测提问（限 2000 字）
- 命中 `high` / `medium` 风险等级（`CONTENT_SECURITY_BLOCK_LEVELS=high,medium`）→ 拦截
- 拦截后**立即返回固定话术** `BLOCKED_REPLY`（"抱歉，这个问题我暂时无法回答…"），不再进入后续任何环节
- 未配置 RAM AccessKey 时自动禁用（跳过）；调用异常时 fail-open（放行并打印告警），保证护栏故障不拖垮主链路

## 4. ② 记忆加载（可选，`src/pipeline.py:_load_profile/_load_history`）

**启用条件**（三者同时满足）：

```
use_memory=True 且 session_id 非空 且 vector_store == "dashvector"
```

不满足则跳过整节，`history_str=""`、`profile_str=""`。

### 4.1 用户画像（长期记忆）

`_load_profile(question)`：调 `MemoryStore.retrieve_global(question, top_k=10)`，在 `chat_memory` collection 里按 `user_id + memory_type=global` 过滤，语义检索出最相关的长期事实，拼成 `- 事实` 列表。

### 4.2 对话历史（短期记忆）

`_load_history(question)`，两层结合：

1. **滑动窗口**：最近 `memory_window=3` 轮（保存在内存 `_recent_turns`）直接以纯文本带入
2. **语义召回**：`MemoryStore.retrieve_session(question, top_k=memory_top_k=4)`，按 `session_id + memory_type=session` 过滤做向量检索，召回更早的相关轮次；与窗口内轮次按 `turn_id` 去重后合并

> 历史文本格式：`用户：<问题>\n助手：<回答>`，多轮用空行分隔。

## 5. ③ 意图识别（`src/retrieval/intent_analyzer.py`）

`IntentAnalyzer.classify(question, history)` 用 LLM 对问题做**三分类**，只输出标签：

- `单意图`：意图唯一且足够明确（表述简短也能安全推断）→ 走改写
- `多意图`：两个以上明确并列意图 → 走拆解
- `需追问`：模糊、歧义或信息不足，无法安全推断唯一意图 → 走追问

解析失败默认按**单意图**（宁少拆）。传入 `history` 用于消解指代，判断"它/那个"能否靠历史解决。

## 6. ④ 改写 / 拆解 / 追问（三选一）

### 6.1 单意图 → 改写澄清（`src/retrieval/rewriter.py:QueryRewriter.rewrite`）

- 把模糊/简短/含指代的问题改写成**一句**意图单一、清晰的检索问题
- 规则：不扩成多意图、括号内最小补充歧义、一句话、≤50 字
- **指代消解**：若第 ② 步有历史，把历史拼进 prompt，让 LLM 把"它/那/第二步"还原成具体对象
- 输出带 `[综合改写]` 标记，解析失败则回退原问题
- 改写结果**只用于检索**，不影响最终展示给用户的原问题

### 6.2 多意图 → 问题拆解（`src/retrieval/decomposer.py:QueryDecomposer.decompose`）

- 只有确认含 2 个及以上独立意图才拆成子问题，每个一行，**最多 4 个**（宁少勿多）
- 单意图则原样输出该问题（一行）
- 拆出的子问题在后续逐个独立检索

### 6.3 需追问 → 交互澄清（`src/retrieval/clarifier.py:Clarifier.ask`）

仅当**同时满足** `use_clarify=True`、`session_id 非空`、且调用方提供了 `clarify_callback` 时启用（即交互式多轮；单次 CLI 与评测自动回退改写）：

1. `Clarifier.ask` 用 LLM 生成**一个最关键的具体追问**（不问空泛问题）
2. 通过 `clarify_callback` 把追问交给用户并接收补充
3. 把"原问题 + 追问 + 补充"合并后重新做意图识别
4. 循环直到意图清晰（转改写/拆解）或达到 `clarify_max_rounds=3` 上限
5. 超限或用户放弃（空输入）→ 强制按**单意图改写**兜底（宁答不错）

> 追问轮不写记忆：只有最终生成答案的那轮才写会话记忆与全局画像。

### 6.4 关闭意图识别时的旧流程

`--no-intent` 时回退为：改写 → 拆解（顺序执行，不再三选一）。

## 7. ⑤ 检索生成

子问题 ≤1 个走 `_single_pass`，多个走 `_multi_pass`。

### 7.1 单路处理（`_single_pass`）

```
_single_pass(query, answer_question)
  ├─ 标签抽取   TagExtractor.extract(query)
  ├─ 混合检索   FusionRetriever.retrieve(query, tag)
  ├─ 重排       Reranker.rerank(nodes, query)  → top_n 个
  └─ 生成       AnswerGenerator.generate(answer_question, nodes, history, profile)
```

#### 7.1.1 标签抽取（`src/retrieval/tag_extractor.py:TagExtractor.extract`）

- 闭集分类：LLM 从 `TAG_LIST`（大模型基础 / RAG基础 / 提示词 / 评测 / RAG优化）中**必须且只能选一个**，与标签都无关则输出"无"
- 返回值不在标签集内则返回 `None`（视为无标签）
- 打印 `[tag] 问题标签: X`

#### 7.1.2 混合检索（`src/retrieval/retriever.py:FusionRetriever.retrieve`）

**语义路**（始终执行）：
```
index.as_retriever(similarity_top_k=20).retrieve(query)
```
LlamaIndex 统一接口，本地与 DashVector 都走向量相似度召回 top-20。

**标签路**（仅 DashVector 且抽到了标签时执行）：
```
collection.query(filter="tag='X'", topk=40)   # 纯字段过滤，无向量
```
按标签字段过滤出该类别最多 40 个块，初始 score=0.0。

**合并去重**：两路结果按 `node_id` 去重，重复项保留分数更高者。

> 本地模式 `indexer.collection=None`，标签路自动跳过——此时 `[tag]` 只是打印，不参与召回。

#### 7.1.3 重排（`src/retrieval/reranker.py:Reranker.rerank`）

- 优先 `DashScopeRerank(top_n=3, model="qwen3-rerank")`（DashScope 专用重排端点，交叉编码器式精排）
- 未安装对应包时回退 `LLMRerank`（用 LLM 打分精排）
- 把粗排候选精排到 `rerank_top_n=3` 个，交给生成

#### 7.1.4 生成（`src/generation/generator.py:AnswerGenerator.generate`）

1. **拼接上下文**：对每个 top-n 块，生成引用标签 `[i]（file_name · header_path）` 拼在块文本前，同时收集 `Source` 列表（index/text/score/header_path/file_name）
2. **填提示词**：用 `RAG_ANSWER_TEMPLATE`（`src/generation/prompts.py`）组装：
   - 【对话历史】history（无则"（无）"）
   - 【参考资料】context_str（各块拼接）
   - 【问题】query_str（注意：多轮时为原始问题，改写只影响检索）
3. **grounding 约束**（prompt 内的三条核心规则）：
   - 只依据【参考资料】回答，不得臆测
   - 资料不足则直接说明"参考资料中未找到相关内容"
   - 答案末尾列出实际引用的资料编号
4. **画像注入**：若有 profile，作为 system prompt 注入（与正文隔离）
5. **LLM 调用**（`src/generation/llm.py:LLMClient.invoke`）：OpenAI 兼容协议，`temperature=0.1`、`max_tokens=1024`
6. 返回 `Answer(answer, sources)`

### 7.2 多路处理（`_multi_pass`）

```
_multi_pass(question, sub_questions)
  ├─ for sub in sub_questions:
  │     _single_pass(sub, sub)          # 每个子问题独立检索+生成
  │     收集 qa_pairs 与 sources
  └─ decomposer.merge(question, qa_pairs)   # 整合子答案
       └─ 返回 Answer(merged, merged_sources)
```

- 每个子问题独立走完整"标签→检索→重排→生成"
- `merge`（`src/retrieval/decomposer.py:MERGE_PROMPT`）：把"子问题+子答案"对整合成连贯最终回答，要求覆盖关键信息、**不编造子答案中没有的内容**

## 8. ⑥ 输出护栏（`src/safety/guard.py:ContentGuard.check_output`）

- 调用 `llm_response_moderation` 服务检测最终回答（限 5000 字）
- 命中拦截等级时，回答替换为固定话术 `BLOCKED_REPLY`，`sources` 清空
- 与输入护栏一致：未配置 AccessKey 自动禁用；异常 fail-open

## 9. ⑦ 记忆写回（可选，`src/pipeline.py:_record_turn`）

仅当第 ② 步记忆启用时执行：

1. `turn_id` 自增
2. `MemoryStore.add_turn(question, answer, turn_id)`：把本轮"用户问题 + 助手回答"拼成一条文本，向量化后写入会话记忆（元数据含 `session_id / memory_type=session / turn_id / timestamp`）
3. 更新内存滑动窗口 `_recent_turns`（只保留最近 `memory_window` 轮）
4. `GlobalMemoryExtractor.extract(question, answer)`：用 LLM 从本轮抽取**长期用户事实**（身份/职业/偏好/学习目标等），逐条 `add_global_fact` 写入全局记忆（`memory_type=global`）；抽取失败仅告警不影响主流程

## 10. 返回

`Answer` 对象：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `answer` | str | 最终回答文本（含引用标注） |
| `sources` | List[Source] | 实际用于生成的文档块（index/text/score/header_path/file_name） |

# 第四部分：开关与模式差异

## 4.1 在线流程可开关项（`pipeline.query` 参数 / CLI 标志）

| 参数 | CLI 开关 | 默认 | 关闭后行为 |
| --- | --- | --- | --- |
| `use_guard` | `--no-guard` | 开 | 跳过输入/输出护栏 |
| `use_memory` | `--no-memory` | 开 | 跳过记忆读写 |
| `use_intent` | `--no-intent` | 开 | 回退"改写→拆解"旧流程 |
| `use_clarify` | `--no-clarify` | 开 | 关闭追问澄清（仅交互多轮有效） |
| `use_rewrite` | `--no-rewrite` | 开 | 用原问题直接检索 |
| `use_decompose` | `--no-decompose` | 开 | 不拆子问题 |
| `use_tag` | `--no-tag` | 开 | 跳过标签抽取与标签路召回 |
| `use_rerank` | `--no-rerank` | 开 | 粗排结果直接用于生成 |
| `top_k` | `--top-k N` | `rerank_top_n=3` | 覆盖最终用于生成的块数 |

> 开关组合可用于消融实验（Ablation）：分别关掉某环节对比 Ragas 指标，量化各环节贡献。

## 4.2 本地 vs DashVector 差异

| 能力 | 本地 JSON | DashVector |
| --- | --- | --- |
| 语义检索 | ✓ | ✓ |
| 标签检索（字段过滤） | ✗（自动跳过） | ✓ |
| 多轮记忆 | ✗（自动关闭） | ✓ |
| 依赖 | 零依赖 | 需 API Key + collection |
